# Changelog

## Recent releases

- `design-review` 1.7.0: the design loop measures type and layout craft from the DOM in the audit tier, per screenshot viewport and scheme: `type.small-text` (under 12 px), `type.scale-near-duplicate` (adjacent sizes under 10 percent apart, each used twice), `layout.edge-near-miss` (text edges 1 to 6 px apart in one landmark) and `type.families` (more than 3), and `type.widow` (a lone last word in a heading or bold text of 16 px or more) inside the width sweep with its bands. Jev gets one visual question, `tell.sparse`, in a call of its own with the whitespace rules, a labeled NO and YES example and shots cut 24 px below the last content, so its context cannot shift the shared questions, whose request stays as in 1.6.0. Line length, line height, a spacing grid, edge and weight counts, and the Jev hierarchy, focal point and grouping questions were measured and dropped; the references say why.
- `writing-core` 1.6.0: the gate warns on a sentence that tells readers how to operate the page itself ("swipe the diagram sideways", "click here", "siehe unten"), with DE and EN patterns that leave product behavior and how-to steps inside a product quiet; `ai-tells.md` names the tell and its fix (design, or an `aria-label` for a screen reader hint). HTML input now gates `figcaption` and a `mermaid-legend` caption as prose; only the diagram source (class `mermaid`) is skipped.
- `design-review` 1.6.0: the design loop checks the visible page text for the same tell, exactly by pattern first, then with one typed Jev question on the text alone (thresholds 0.85 and 0.35 from 16 synthetic pages, alone and inside a long page) and the model when Jev is unsure; a text-only Jev call no longer sends the image opt-in. Also ships the card alignment check merged after 1.5.0: `layout.alignment` measures matching card parts over a 360 to 1592 px width sweep, and Jev asks `tell.misaligned-cards`.

- `design-review` 1.5.0: the design loop shoots each diagram on its own (a large `svg`, `canvas`, `figure`, or `[role=img]`, up to 6, sticky layers hidden and clipping containers opened), because a diagram below the first 1568 px never reached the page screenshots. It checks clipped text, stacked labels, lines through boxes, and small text: exactly from the geometry of inline SVG, otherwise with typed Jev questions whose thresholds come from 7 synthetic diagrams, and the model for what Jev is unsure about. Jev is asked every diagram rule, also those the DOM proved, because its answers shift with the question set.
- `estimate-with-uncertainty` 1.0.0: computes estimates and forecasts (cost and budget, capacity and headcount, volume and KPI projections) from small, messy operational data as ranges with their basis: value and threshold before size, a data-situation-to-method table (Bayesian lognormal regression with weakly informative priors, shrinkage for small groups, open items as lower bounds, a dispersion check before Poisson, resampled period counts, Bayesian rate regression instead of p-values, queue simulation with a wait target, Erlang C and N+1), three separate ranges (expected period, period to period, predictive), mean or median by purpose, sensitivities in the method details, one method with a correction log, and a reproduce check of every stated figure; a stdlib sketch with tests and an 11-source registry. `check-knowledge.py` resolves a citation registered in another family.
- `plain-numbers` 1.3.1: rule 10 points to `estimate-with-uncertainty` for computing a forecast.
- `design-review` 1.4.2: the design loop starts when run through the installed symlink (its main check compares real paths), `--help` prints usage, and Playwright is looked up in the current project, then beside the script, then fails with the exact install command.
- `design-review` 1.4.1: the design loop refuses an escalation model from a provider outside the approved list (Anthropic, OpenAI, Google) or from a restricted-jurisdiction model family, matched anywhere in the id, unless that exact id is in `OWNER_APPROVED_MODELS`.
- `design-review` 1.4.0: `scripts/design-loop.mjs` reviews a page after every UI change, cheapest check first: screenshots at 1280 and 390 px in light and dark, generic-look tells read from the DOM, the reading audit, typed Jev questions on the screenshots, and a vision model only for the rules Jev is unsure about; one JSON report with rule, tier, confidence, evidence, and cost, exit 1 on a failure, every model call with zero data retention and no prompt training. On 8 pages it found 21 of the 22 rule failures a vision-model reviewer found at about 2% of its cost.
- `design-core` 1.4.0 and `frontend-craft` 1.9.0: done includes a design loop run on every changed page or screen.
- `scaffold-harness` 3.3.0: the workspace root `AGENTS.md` routes a session that changes an interface another repository uses to the map's Relationships rows and a sibling search for its consumers, adds the replacement and migrates every consumer it may change before the provider's removal merges, and keeps the old shape until every deployed consumer reads the new one; the map template's relationship row names the consumer files that read the contract.
- `write-a-skill` 1.7.0: the hard limits of a portable Skill (the six spec fields only; host-only fields such as `when_to_use`, `paths`, or `disable-model-invocation` go into target-local copies), the shared listing budget (trigger in the first sentence of about 150 characters, about 350 characters overall, the closest neighbour named, the live listing checked after adding a Skill), host discovery facts with Antigravity or Gemini CLI and pi, standing rules in the first screen because compaction keeps 5,000 tokens, a body size target, the boundary between an always-loaded index and a Skill, and a concrete trigger eval (about 20 prompts, half near-misses, 3 runs, a held-out part) with a RED baseline and a no-guidance control.
- `writing-core` 1.5.0: `agent-readers.md` puts the most important rules first, keeps a context file under about 200 lines and inside Codex's 32 KiB, moves always-true rules into hooks, sets scope and delegation in briefs instead of blanket verify lines, marks pasted text as data, notes that CLAUDE.md strips HTML comments, verifies the contradiction rule against the Claude Code documentation, and states the ETH context-file result with its version and the non-significant +2.4 percent; the description is shorter.
- Shorter descriptions (patch releases, about 350 characters each, trigger, neighbour, and German trigger words kept) so more of the catalog keeps its description in a host's shared skill listing: `writing-editorial` 1.1.1, `writing-engineering` 1.2.1, `writing-marketing` 1.1.1, `writing-product` 1.3.1, `design-core` 1.3.1, `design-dataviz` 1.1.1, `design-flows` 1.1.1, `design-forms` 1.1.1, `design-product-ui` 1.3.1, `design-research` 1.2.1, `design-review` 1.3.1, `design-slides` 1.1.2, `design-systems` 1.1.1, `design-web` 1.3.1, `frontend-craft` 1.8.1, `product-craft` 1.5.1, `run-product-engineering` 2.1.1, `scaffold-harness` 3.2.1.
- `playwright-best-practices` 2.0.0: browser tests locate every element by `data-testid` with `getByTestId`, never by role, label, text, or CSS, so copy, translation, theme, and layout changes do not break them; ids are named by purpose (`row-<id>`, `account-menu`), and accessibility is covered by axe scans plus explicit role and name assertions, not locators.
- `testing-strategies` 1.7.0: the e2e and accessibility rows and red flags follow the test-id locator rule.
- `testing-strategies` 1.6.0: the risk mapping adds a row for a new or changed route, handler, or stream (at least one test through the real route), runs accessibility checks over every reachable state such as a dialog, toast, error, empty, or loading view, and makes the pull request build and boot the deployable artifact, with a Dockerfile, base image, runtime, toolchain, lockfile, or dependency major change counted as a boot-path change. Levels stay a judgment; check untested states and mocked-away routes first.
- `scaffold-harness` 3.1.0: scaffolds a multi-repository workspace as well as one repository - a workspace root `AGENTS.md`, a coordinator with `CONTEXT-MAP.md`, `SYNC.md` (working root, admission, sibling awareness, fan-out, write-back), and `STATUS.md` (worktree leases), and a member snippet every member's `AGENTS.md` carries; the template `HARNESS.md` gains **Repository and Team Topology** and a **Leases** item. Single-repository use is unchanged.
- `agent-sync` 2.1.0: routes workspace-wide rules and lessons to the coordinator per its `SYNC.md` **Write-back**, and membership and contracts to its `CONTEXT-MAP.md`.
- `deliver-dependency-upgrades` 1.2.0: a compiler, runtime, or framework major counts as admissible only when the tools that wrap it (type checkers, lint plugins, test runners, framework checkers) accept it in their registry peer ranges; when one excludes it, the decision is `defer` with the blocking peer and what would lift it.
- `completion-gate` 1.9.0: the merge gate refuses a green pull request whose diff adds a git conflict marker (exit 5) and fails closed when gh cannot provide the diff; a bare required name matches a check's job part, skipped checks are neutral, and a refusal lists every check seen per required name.
- `shift-left-security` 1.0.0: security from the first line of a change - threat note, abuse-case test first, the platform's safe default (shift down), the control at the owning boundary, sessions and tokens, dependency verification and cooldowns, CI script injection and OIDC, zero trust paths, agent and MCP features, rules for the agent itself, and a list of retired folklore, backed by a 36-source registry opened on 2026-10-26.
