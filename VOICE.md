# Repository Voice

I want this repository to sound the way I work: direct, specific, and grounded
in system effects. It should never read like an AI consultancy brochure.

Name reality, build a working system, make trade-offs and ownership visible,
and keep human accountability intact while people and agents change the
product.

## Stance

- Start with the problem, value, constraint, or observed signal.
- Treat product, engineering, delivery, and operations as one learning system.
- Prefer shared ownership, visible flow, built-in quality, and production
  feedback over role or process theater.
- Use a framework, method, model, or tool only when it improves the actual
  system.
- Let AI increase leverage without reducing accountability.
- Lead with the working model we want. Use contrast only when it makes a
  boundary clearer.

## Writing

- Be direct, specific, and grounded.
- Use concrete subjects and verbs. Name the owner, signal, constraint, system
  effect, or next action when it matters.
- State the trade-off. Do not sell a decision as cost-free.
- Explain why only when the reason changes a decision or prevents a likely
  mistake.
- Keep one job per paragraph. Prefer a short sentence over a chain of abstract
  nouns.
- Define specialized language where the audience cannot infer it.
- Use a table only when comparison is clearer than prose.
- Write tracked artifacts in idiomatic US English with ASCII punctuation.

## Useful Structures

For a recommendation:

```text
current signal -> read -> trade-off -> next useful step
```

For an agent procedure:

```text
goal -> inputs and authority -> actions -> checks -> stop and recovery
```

For a human guide:

```text
what you get -> how it works -> evidence -> where to start
```

For a durable learning:

```text
observation -> implication -> system change or re-check trigger
```

## Delete Slop

Remove:

- generic hype and stock model phrases
- adjectives that claim quality without naming a standard or effect
- long stacks of abstract nouns
- repeated summaries that add no decision or action
- defensive setup before the actual point
- negative contrast used as the main story
- fake certainty, completeness, or universal best practice
- prose that sounds intelligent but changes nothing

Use two tests:

1. Could this sentence appear unchanged on any AI consultancy website? Rewrite
   or delete it.
2. Which decision, action, or understanding changes because this sentence
   exists? If none, delete it.

## Boundaries

Writing in my voice does not mean sprinkling preferred phrases into every file.
Technical precision beats personality. Safety, authority, legal meaning, and
source fidelity are not simplified away for tone.

First person is reserved for owner-authored artifacts that explicitly speak for
me, such as the main README and this file. Keep agent instructions and operating
procedures neutral and imperative.

Sharp does not mean hostile. Critique the system effect, show the better
working model, and make the next move clear.

The static audit catches only high-signal cliches. Human or agent review still
owns vague, repetitive, defensive, or behavior-neutral prose.

The audit ignores fenced code, inline code, and Markdown blockquotes. If an
exact source title or product term still trips a rule, add
`<!-- prose-audit: allow -->` on that line. The surrounding text must make the
reason clear.
