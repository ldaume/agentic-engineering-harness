# Website Content

A website serves several information needs and navigation paths; a landing
page serves one. Start from user need and information architecture. Write
people-first content with clear titles and real added value, never mechanical
summaries or mass content for rankings.

## Per page

Primary page purpose, primary user question, answer, supporting evidence and
details, related next paths.

## Site

- Homepage: value and orientation.
- Service or product pages: specific jobs and outcomes.
- Evidence and cases: credibility.
- About: who, why, how.
- Knowledge and docs: useful depth.
- Contact or conversion: the next conversation.

## Workflow

1. Inventory user intents.
2. Give each page one primary intent.
3. Remove duplicate ownership across pages.
4. Write title and H1 before paragraphs.
5. Front-load the answer.
6. Put evidence where claims occur.
7. Add descriptive internal links (link text says where it goes, never "click
   here").
8. Check the page stands alone when entered from search or a share.
9. Review global terminology.
10. Review periodically for ownership and freshness.

First propose the information architecture. Never pad to a target word count;
there is no SEO-preferred length. For SEO or site structure strategy, the
`seo-audit` and `site-architecture` skills own the analysis when installed;
this file owns the prose.

## Golden excerpt

Input: the security and compliance page of a B2B SaaS product; primary reader
is an enterprise admin or security lead checking whether the product supports
their audits.

<!-- golden: website_content en -->
```text
# Security and compliance evidence you can pull yourself

Your workspace records an audit log of every admin and data action. Admins
export it on demand, scoped to their role, for audits and security reviews.

## What the audit log records

Sign-ins, permission changes, exports, and deletions, each with actor, time,
and affected workspace.

## Who can export it

Any admin role with audit access. The export never includes data the role
cannot already see in the product.

Next: [See the audit log fields](#) or [Read how roles work](#)
```

<!-- golden: website_content de -->

```text
# Sicherheits- und Compliance-Nachweise, die du selbst abrufst

Dein Workspace protokolliert jede Admin- und Datenaktion in einem Audit-Log.
Admins exportieren es bei Bedarf, begrenzt auf ihre Rolle, für Audits und
Sicherheitsprüfungen.

## Was das Audit-Log aufzeichnet

Anmeldungen, Änderungen an Berechtigungen, Exporte und Löschungen, jeweils mit
Person, Zeitpunkt und betroffenem Workspace.

## Wer es exportieren darf

Jede Admin-Rolle mit Audit-Zugriff. Der Export enthält nie Daten, die diese
Rolle im Produkt nicht ohnehin sieht.

Weiter: [Felder des Audit-Logs ansehen](#) oder [Lesen, wie Rollen funktionieren](#)
```

Pages drafted with AI pass the same test as any page: added value for the
reader and a manual fact-check of body and metadata - title, meta
description, structured data, alt text (verified) [SRC-WRITE-006].

Checks: primary intent answered early, descriptive H1 and headings, a useful
internal next path, a distinct job per page, original value.
