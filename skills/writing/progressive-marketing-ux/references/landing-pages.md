# Landing Page

Unlike a website, a landing page serves one narrow audience and one specific
next action. It needs one clear goal, one clear CTA, and message match with
the traffic source or campaign promise.

## Architecture

Message match or hero, problem or desired state, value or outcome, how it
works, proof, relevant details, objection or risk reduction, CTA, optional
FAQ.

Progressive variant: what you get, how it compounds, how it works, evidence,
conditions and context, next conversation.

## Workflow

1. Identify one segment.
2. Identify one entry promise.
3. Identify one conversion action.
4. Make the hero satisfy the entry promise.
5. Put proof next to the claim it supports.
6. Explain the mechanism before piling up feature bullets.
7. Handle only real objections.
8. Repeat the CTA where the reader has enough information to act.
9. Remove navigation and content that serves another intent on a campaign
   page.
10. Test the message, not just the button color.

Length: no universal word target. Use the minimum the decision needs: simple
signup 250 to 600 words, B2B consideration 500 to 1,500, high-risk or
high-cost decision as much as the evidence requires.

Create the page architecture first, then draft each section. Flag a claim that
lacks evidence instead of inventing proof.

## Template

```text
# [Outcome]

[Value + mechanism]

[CTA]

## [The situation / problem]
## [What changes]
## [How it works]
## [Proof]
## [Relevant concerns]
## [Next step]

[CTA]
```

```text
Du startest den Export selbst, wann du ihn brauchst. Die Datei enthält das
Audit-Log, das dein Workspace ohnehin aufzeichnet.

darfst, steht auch nicht in der Datei.

```
